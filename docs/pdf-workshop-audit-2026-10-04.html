PDF accessibility workshop: real-form audit

October 4, 2026 · localhost · PR #300

The automatic repair pass completed on all 56 unique PDFs (57 source templates, 125 pages). The tool still cannot fully remediate every supplied PDF.

All raw widget names, types, flags, values and rectangles were preserved, as were page dimensions. All 56 outputs passed qpdf. No new PDF/UA declarations were added.

veraPDF keyboard-navigation failures fell from 47 to zero (the baseline count includes one duplicate template). The new pass set 19 page flags and repaired 22 viewer-title flags. Existing CIDSet failures were eliminated by the existing automatic font repair.

54 PDFs rendered pixel identically. The other two—Appeals Civil Docketing Statement and the 9-page SSA-632—showed font rasterization differences. Visual inspection found no layout shift; nearly all ink remained within one pixel of its original position.

Fixes from this exploration

  • Apply structure-based Tab navigation independently of a field-order payload, including link-only pages.
  • Enable display of an existing document title automatically.
  • Place the duplicate-name summary outside the inert editor, above the workshop, and wait for dismissal.
  • Find captions touching signature blanks; avoid neighboring court headings and unrelated signature rows in label suggestions.
  • Expose controls with empty internal names for descriptions without renaming them. Preserve those decisions through rebuilds and Undo.
  • Invalidate external test records, AI findings and declaration consent when the PDF changes; Undo restores the corresponding recorded tests.
  • Import inserted pages’ fields into the editable list so export can deduplicate the complete output while reserving every original name.
  • Register split/copied field trees, prune omitted widgets, and preserve field values and default fonts. Retain unnamed controls, their appearances and actions during field export.
  • Constrain OpenCV to versions that provide the field detector’s groupRectangles function. Both automatic detection and AI relabeling now pass on real files.
  • Route generic OCR for blank signature boxes through the preserving text-layer repair. Populated signatures continue to use the original signature-protection path.

Decisions and remaining gaps

1. Create and repair table semantics

Example: Appeals Civil Docketing Statement, page 2; SSA-6233 dedicated-account tables; Housing Code Checklist existing tables

The workshop can confirm the first header row and pad existing table tags. It cannot create an untagged table, define arbitrary cells/merged cells, or repair invalid P children inside TR in its browser UI. The Appeals form has a visible table but no detected table tags. Keeping broken original tags leaves failures; replacing them can flatten table semantics.

Decision: Prioritize a cell-based table editor if every supplied PDF must be fully accessible; decide which header/grouping choices require authors.

2. OCR and block splitting

Example: Scanned 209A plaintiff motion and 11-page SSA-6233

OCR works and rebuilds the tree, but the 209A header joins motion text with the docket/court column. It also reads I as |. ActualText corrections are available; there is no browser control to split a block into separate semantic elements. Whole-page scan images remain explicit image decisions.

Decision: Add block splitting/merging and a guided OCR review. Decide how authors confirm that a scanned background carries no information beyond the verified text.

3. Decorative objects encoded as buttons

Example: CRA motion court seal and Print Form control with empty /T

The fix exposes both controls for accessible descriptions and preserves their empty internal names. The Print Form caption is a useful draft. Naming the seal can pass technical checks while leaving a meaningless button role.

Decision: Support an explicit keep-control versus flatten-to-decoration choice; preserve the seal appearance when removing its interactive role.

4. Missing fonts and ambiguous glyphs

Example: 12 PDFs still fail veraPDF font embedding; 8 retain built-in Unicode mapping failures after the automatic pass

Exact installed-font embedding and proven CIDSet repairs are automatic. Missing font programs and ambiguous symbols cannot be inferred safely. The existing substitution and glyph-review controls need visual confirmation.

Decision: Decide which font substitutions are acceptable for court forms and provide source fonts when they must be preserved.

5. External assistive-technology verification

Example: CRA motion has zero built-in failures; veraPDF only reports its deliberately absent PDF/UA identifier

No new PDF/UA declarations were added. Browser replay and machine checks do not establish correct semantics or actual Acrobat/NVDA/JAWS behavior. External and AI evidence now resets when PDF content changes; Undo restores recorded tests with the corresponding PDF.

Decision: Require a real screen-reader and keyboard pass before authors declare conformance. Set an acceptance checklist for table navigation, signatures, links, and required controls.

6. Page changes require renewed accessibility review

Example: Page-manager split, remove and insert check

Page assembly creates a new PDF and does not carry over document tag trees. The fix imports inserted fields as editable overlays, enabling complete occurrence-level deduplication on export. Splits now register live field trees, retain values and default fonts, and deduplicate exact names with an occurrence summary. Inserted-page export retains unnamed controls as well. The resulting documents still need accessibility review because document tag trees are not carried over.

Decision: Decide whether tagged documents should require an explicit warning/acknowledgment before rearranging pages, or whether preservation of existing tags must be implemented.
